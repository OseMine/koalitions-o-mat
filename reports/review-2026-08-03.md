# Koalitions-O-Mat – Bugfix-Implementierung vom 2026-08-03

Bugfix-Lauf zu Issue „[Bug]: resolve Bugs" (siehe `todo.md`). Alle in `todo.md` offenen P1-/P2-Befunde sowie ausgewählte P3-Befunde wurden umgesetzt. Status per Node gegen die echten Datendateien und gegen `script.js` verifiziert (`node --check script.js` OK, alle JSON valide, i18n-Key-Check vollständig).

## Umsetzung

### P1 – Bugs

- [x] **Einfache Sprache beim Reload nicht angewendet** – `applyStaticI18n()` wird in `loadElections()` (script.js:335-337) nach dem Fetch von `einfache-sprache.json` erneut aufgerufen; alle statischen `[data-i18n]`-Texte erscheinen jetzt auch bei `simpleLang=1` nach einem Reload in einfacher Sprache.
- [x] **`createSeatChart()` ohne Leer-Guard** – bei keiner Partei über der Sperrklausel zeigt `createSeatChart()` jetzt `showChartPlaceholder('seatChart', …)` statt eines leeren Pie-Charts „0 Sitze" (script.js:1261-1266).
- [x] **Rein neutrale Antworten → 0 %** – `showTestResults()`: `match` ist bei `total === 0` jetzt `null` (Anzeige „–" statt 0 %); Pie-Chart und `saveTestResult()` entfallen bei `usableAnswered === 0`; neuer `neutralHint` („Neutrale Antworten ({n}) fließen nicht in die Übereinstimmung ein."); `berechneUserMatchFuerKoalition()` liefert bei 0 verwertbaren Antworten `null` statt 0 (Anzeige „–", Sortierung ans Ende via `?? -1`).
- [x] **`noPartyInfo`-Key mit zwei Fallback-Texten** – zweiter Text nutzt jetzt den eigenen Key `partyInfoPending` (script.js:436).
- [x] **Hartkodierte Strings** – `sourceLabel` („Quelle: "), `questionCol`/`youCol` (Tabellenkopf „Frage/Sie"), `legendAgree`/`legendDisagree`/`legendNotComparable` (Legende ✓/✗/—), `simpleLangLabel` (Toggle-Label, index.html:22, jetzt mit `data-i18n`).

### P2 – Fehlende Features

- [x] **„Fortsetzen" springt nach Reload zu Frage 1** – `saveTestState()` speichert `currentQuestion`; `initializeTest()` stellt die Position wieder her (geclampt auf gültigen Bereich); `showNextQuestion()`/`showPreviousQuestion()` persistieren die Position.
- [x] **`saveTestResult()` bei 0 verwertbaren Antworten** – Speicherung nur bei `usableAnswered > 0`; übersprungene Tests verdrängen keine echten Ergebnisse mehr aus der Historie/Themenverteilung.
- [x] **Teilen-Link verliert neutrale Antworten** – `shareResults()` kodiert jetzt auch `m`-Antworten (Filter j/n/m); Roundtrip per Node verifiziert (`0j1m2n` → `{"0":"j","1":"m","2":"n"}`).
- [x] **Parteien mit wenigen beantworteten Fragen** – Partei-Karten zeigen „Nur X von N Fragen beantwortet" (`fewAnswersHint`); verifiziert: Berlin Volt/Tierschutz nur 3/52.
- [x] **„Ergebnis teilen" im Koalitionen-Tab** – `shareResults()` hängt `&c=` an (Typ|Mindestmatch|Partei-Filter|Ausschlüsse), `parseShareHash()`/`applyPendingShare()` stellen die Koalitions-Sicht wieder her; Alt-/Neuformat bleiben kompatibel.
- [x] **Partei-Filter-Dropdown inkonsistent** – Filter listet jetzt alle antwortenden Parteien (auch unter der Sperrklausel, z. B. FDP/BSW in btw2029).
- [x] **Cross-Election-Leak** – `window.parteienData = data.fragen || null`; `initializeTest()` zeigt bei fehlenden Fragen einen Empty-State statt Fragen der letzten Wahl.
